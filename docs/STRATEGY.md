# 보유 장비 기반 개발 전략 (2026-11-15 작성)

## 1. 보유 장비 현황

### 로봇 본체 (점검 완료)

| 구성 | 상태 |
|---|---|
| AX-12A 18개 (ID 1~18) | 전부 PASS. 표준 BIOLOID Type A 배치와 일치. 1번만 위치 센서 흔들림 3 tick(경계값) |
| AX-18A 그리퍼 2개 (ID 19 오른쪽, 20 왼쪽) | 혼을 180° 재조립하고 관절 모드로 전환. 이동량 160°, 각도 제한 설정 완료 |

| 자이로 (2축) | CM-530 3, 4번 포트. 순정 태스크가 걸음 보정에 사용 |
| 거리 센서 (DMS) | CM-530 5번 포트. 순정 자율 보행·데모 모드가 사용 |
| 적외선 수신기 | CM-530 WIRELESS 포트 (현재는 BT-210으로 교체된 상태) |
| CM-530 내장 | 마이크(박수 횟수), 부저, 버튼 |

### 예비 부품과 주변 장비

| 장비 | 비고 |
|---|---|
| AX-18A 10개 | 다리 강화용 (AX-12A보다 토크 약 20% 높고 빠름) |
| MX-64 2개 | 토크 6N·m. 통신 방식(TTL/RS-485) 미확인 → 커넥터 핀 수로 확인 필요 |
| USB2Dynamixel, SMPS2Dynamixel, 12V 5A 어댑터 | PC 직접 제어용. 현재 CM-530의 남는 DXL 포트에 USB2Dynamixel 연결 |

| ZIG 모듈 1개 | 짝이 없어서 현재 사용 불가 |

| 메카넘 휠 2개 | 전방향 이동에는 4개 필요 |
| 3D 프린터, LiPo 충전기, iPhone, iPad, Mac | iPhone은 Mac의 연속성 카메라로 웹캠처럼 사용 가능 |

## 2. 핵심 제약

1. **CM-530에 새 태스크를 넣는 통로가 막혀 있음.** Mac용 R+ m.Task2는 BT-410만 지원하고 BT-210·USB는 지원하지 않습니다. 해결하려면 BT-410 구매 또는 Windows PC + 미니 USB 케이블이 필요합니다.
2. **CM-530은 영상 처리 불가.** 비전은 PC가 맡아야 합니다.
3. **모터 선에는 명령하는 장치가 하나여야 함.** CM-530과 PC가 동시에 명령하면 충돌합니다. 그리퍼처럼 CM-530이 쓰지 않는 모터만 PC가 맡는 것은 가능합니다.
4. **macOS USB 지연.** 20개 모터 상태를 한 바퀴 읽는 데 약 0.3초가 걸립니다. 명령을 보내기만 하는 모션 재생은 빠르지만, 상태를 읽으며 제어하는 폐루프는 느립니다. Linux(Raspberry Pi)로 가면 해결됩니다.
5. **자이로는 CM-530에만 연결됨.** PC가 직접 제어할 때는 균형 보정이 없습니다. IMU를 따로 달아야 합니다.
6. **AX-12A의 한계.** 토크 1.5N·m, 플라스틱 기어, 위치 센서 300° 범위. 달리기나 점프는 불가능합니다.

## 3. 목표 정의

**1차 목표: "보고 → 다가가서 → 잡기"를 보유 장비만으로 시연한다.**

- 물체는 처음에는 **로봇 가슴 높이의 받침대 위**에 두어, 숙이는 동작 없이 팔만 뻗어 잡게 합니다.
- 물체는 가볍고 그리퍼 폭에 맞는 것(종이컵, 스펀지 블록 등)으로 합니다.

## 4. 단계별 전략

### 0단계. 지금 상태로 원격 집기 (추가 비용 없음, 1일)

- 걷기: 순정 태스크 + 노트북 블루투스 리모컨(`tools.bt_session`)
- 그리퍼: USB2Dynamixel로 PC가 직접 제어 (19, 20번만)
- 키보드 하나로 "걷기·돌기·그리퍼 열기/닫기"를 조종하는 원격 조종 프로그램 작성
- 결과물: **사람이 노트북으로 조종해서 물체를 집는 시연**
- 한계: USB 케이블이 로봇에 연결된 상태

### 1단계. PC 모션 엔진 (추가 비용 없음, 3~5일)

CM-530을 MANAGE 모드로 두고 PC가 모든 모터를 제어합니다.

- 순정 모션 파일(.mtn) 해석 → 걷기·돌기 페이지를 PC에서 재생 (명령만 보내므로 macOS 지연과 무관)
- `pose record`로 "팔 뻗기", "잡기", "들어 올리기" 자세를 손으로 가르치고 이어 붙여 새 모션 작성
- 걷기, 팔 동작, 그리퍼가 모두 PC 한 곳에서 제어되므로 이후 비전과 바로 연결 가능
- 한계: 케이블 연결, 균형 보정 없음 (공중 시험 → 바닥 시험 순서로 안전하게 검증)

### 2단계. 비전으로 다가가기 (추가 비용 없음, 1주)

- 카메라: **iPhone을 연속성 카메라로** 써서 로봇과 물체를 위에서 내려다보게 설치
- 위치 추정: 로봇 머리와 물체에 **ArUco 마커**를 붙여 시작 → 이후 YOLO 등으로 마커 없이 인식 (실무 전문 분야)
- 제어: 물체 방향으로 돌기 → 거리만큼 걷기 → 멈춤 → 팔 뻗기 → 잡기
- 결과물: **로봇이 스스로 물체를 찾아가 집는 시연**

### 3단계. 소액 구매로 완성도 올리기

| 구매 | 효과 | 우선순위 |
|---|---|---|
| BT-410 (슬레이브) | 수정 태스크 무선 내려받기, 저전력 블루투스 조종 | 높음 |
| IMU (BNO085 등) + 소형 마이컴 | PC 제어 시 균형 보정, 넘어짐 감지 | 높음 |
| Raspberry Pi | 로봇에 탑재해 케이블 제거, USB 지연 해결 | 중간 |
| 메카넘 휠 2개 | 바퀴형 이동 베이스 (4번 참고) | 선택 |

### 4단계. 하드웨어 강화 (데이터 기반)

- **AX-18A 다리 교체:** 걷는 직후 관절별 온도 상승을 측정해서 가장 뜨거운 관절부터 교체 (무릎, 발목 피치가 유력)
- **MX-64 무릎:** 통신 방식 확인 후, 3D 프린팅 브래킷으로 장착. 토크 4배
- **바퀴형 양팔 로봇 (대안 플랫폼):** 메카넘 휠 4개 + AX-18A 4개(Wheel 모드) 베이스 위에 상체 장착. 넘어질 걱정이 없어 집기 시연이 훨씬 안정적이고, 산업용 Physical AI 형태에 가까움

### 5단계. 시뮬레이션과 강화학습 (장기)

- 실측 치수와 질량으로 MuJoCo 모델 작성 (그리퍼는 직육면체로 근사)
- 시뮬레이션에서 걸음을 학습한 뒤 실물로 이식
- 전제 조건: IMU, 로봇 탑재 컴퓨터, 3단계 완료

## 5. 추천 순서

1. **0단계**로 내일 바로 원격 집기 시연 (가장 빠른 성과)
2. **1단계 → 2단계**로 자율 집기 시연 (추가 비용 없이 도달 가능한 최종 목표)
3. 시연이 되면 **BT-410 + IMU**를 사서 케이블과 균형 문제 해결
4. 그다음 하드웨어 강화나 바퀴형 플랫폼 중 방향 선택

## 6. 안전 규칙 (오늘 배운 것)

- 처음 보내는 명령은 **로봇을 공중에 든 상태**에서 시험한다.
- 명령은 **하나씩, 짧게** 보내고 결과를 확인한 뒤 다음으로 넘어간다.
- macOS의 `/dev/cu.ROBOTISBT-210` 포트로는 보내지 않는다. 신호가 쌓였다가 연결 순간 한꺼번에 전달된다.
- 블루투스 세션을 연결하면 정지 신호가 나가서 **대기 모드의 로봇이 일어선다.** 연결 전에 미리 알린다.
- 장시간 서 있게 두지 않는다. 지지 관절 온도가 금방 오른다.
